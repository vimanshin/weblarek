# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В первой части проекта реализованы модели данных, коммуникационный слой и загрузка каталога с сервера. Модели не публикуют события. Связь моделей и представлений через презентер, описанная выше, относится ко второй части проекта.

### Товар — `IProduct`

Интерфейс описывает один товар каталога: идентификатор, описание, путь к изображению, название, категорию и цену.

```typescript
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

`price: null` означает, что у товара нет цены: его можно посмотреть, но нельзя купить. Это не то же самое, что `price: 0`.

### Покупатель — `IBuyer`

Интерфейс описывает данные, которые покупатель заполняет при оформлении: способ оплаты, почту, телефон и адрес доставки.

```typescript
type TPayment = 'card' | 'cash';

interface IBuyer {
  payment: TPayment | '';
  email: string;
  phone: string;
  address: string;
}
```

Изначально все четыре поля содержат пустые строки. Для `payment` значение `''` означает отсутствие выбора и не считается способом оплаты.

## Модели данных

### Каталог — `Catalog`

Модель будет хранить список товаров каталога и товар, выбранный для подробного просмотра. Она не зависит от DOM, сетевых запросов и других моделей.

**Конструктор:** `constructor()` — без параметров. Изначально список пуст, товар для просмотра не выбран.

**Поля:**
- `private items: IProduct[]` — список товаров; начальное значение `[]`.
- `private selectedItem: IProduct | null` — выбранный для просмотра товар; начальное значение `null`.

**Методы:**
- `setItems(items: IProduct[]): void` — заменяет список переданным массивом. Пустой массив очищает список. Сохранённый выбор для просмотра не меняется.
- `getItems(): IProduct[]` — возвращает список товаров. Если товаров нет, возвращает пустой массив.
- `getItemById(id: string): IProduct | undefined` — ищет товар по ID в сохранённом списке. Если совпадения нет, возвращает `undefined`. Товар для просмотра не меняется.
- `setSelectedItem(item: IProduct): void` — сохраняет переданный товар для подробного просмотра.
- `getSelectedItem(): IProduct | null` — возвращает выбранный товар или `null`, если выбор ещё не сделан.

При сохранении и выдаче данных модель копирует массив и объекты товаров. Изменение переданного или возвращённого объекта не меняет внутреннее состояние каталога.

### Корзина — `Cart`

Модель будет хранить товары, выбранные для покупки. Она не зависит от каталога, DOM и сетевых запросов. Количество товаров и общая стоимость вычисляются по списку, а не хранятся отдельно.

**Конструктор:** `constructor()` — без параметров. Изначально корзина пуста.

**Поле:**
- `private items: IProduct[]` — список товаров в корзине; начальное значение `[]`.

**Методы:**
- `getItems(): IProduct[]` — возвращает новый массив с копиями товаров. Если корзина пуста, возвращает `[]`.
- `addItem(item: IProduct): void` — сохраняет копию товара. Если товар с таким `id` уже есть или его цена равна `null`, корзина не меняется. Цена `0` не препятствует добавлению.
- `removeItem(item: IProduct): void` — удаляет товар по `id` переданного объекта. Если такого `id` нет, корзина не меняется.
- `clear(): void` — удаляет все товары из корзины.
- `getCount(): number` — возвращает количество товаров в списке. Для пустой корзины возвращает `0`.
- `getTotal(): number` — возвращает сумму цен товаров в списке. Для пустой корзины возвращает `0`.
- `hasItem(id: string): boolean` — возвращает `true`, если товар с таким `id` есть в корзине, иначе `false`.

### Покупатель — `Buyer`

Модель будет хранить и проверять данные покупателя при оформлении заказа. Она не зависит от DOM, сети и других моделей.

**Конструктор:** `constructor()` — без параметров. Изначально способ оплаты не выбран, адрес, почта и телефон не заполнены.

**Поле:**
- `private data: IBuyer` — способ оплаты, адрес доставки, почта и телефон. Начальное значение каждого поля — `''`.

**Методы:**
- `saveData(data: Partial<IBuyer>): void` — обновляет только поля, для которых переданы значения. Отсутствующее поле или `undefined` не меняет сохранённое значение; `''` очищает поле. Модель сохраняет значения полей, а не ссылку на переданный объект.
- `getData(): IBuyer` — возвращает новый объект со всеми четырьмя полями. Изменение этого объекта не меняет данные модели.
- `clear(): void` — сбрасывает все четыре поля к `''`.
- `validate(): Partial<Record<keyof IBuyer, string>>` — возвращает новый объект с текстами ошибок только для полей, не прошедших проверку. Ключ — имя поля из `IBuyer`; если ошибок нет, возвращает `{}`.

Оплата проходит проверку, если выбрано `card` или `cash`. Для адреса, почты и телефона проверяется только заполненность: строка из одних пробельных символов считается пустой. Проверка не меняет сохранённые значения и не проверяет формат почты или телефона.

## Слой коммуникации

### Настройка API

Перед запуском `npm run dev` создайте в корне проекта файл `.env` со строкой:

```dotenv
VITE_API_ORIGIN=https://larek.ffapi.ru
```

Укажите адрес без завершающего `/`: путь API добавляется в коде.
После запуска откройте консоль браузера, чтобы увидеть результат загрузки каталога.

### `WebLarekApi`

Класс будет получать каталог и отправлять готовые заказы. Он делегирует
запросы переданному объекту `IApi`, не наследуется от `Api`, не меняет
модели данных и не управляет интерфейсом.

**Конструктор:** `constructor(api: IApi)` — принимает объект,
через который будут выполняться запросы.

**Поле:** `private readonly api: IApi` — хранит переданный объект.

**Методы:**
- `getCatalog(): Promise<ICatalogResponse>` — без параметров.
  Выполняет `GET /product/` и возвращает весь ответ: `items` с товарами
  и `total` с их количеством.
- `submitOrder(order: IOrderRequest): Promise<IOrderResponse>` —
  принимает готовое тело заказа с данными покупателя, суммой и ID товаров.
  Передаёт его в `POST /order/` и возвращает ответ сервера с ID заказа
  и подтверждённой суммой.

### Типы запросов и ответов

- `IApi` — интерфейс клиента, которому `WebLarekApi` делегирует запросы. Методы `get` и `post` возвращают `Promise<T>`, где `T` — ожидаемый тип ответа.
- `ICatalogResponse` — ответ каталога: `items: IProduct[]` — массив товаров, `total: number` — их количество.
- `IOrderRequest` — тело запроса на оформление заказа: `email`, `phone` и `address` — строки из `IBuyer`; `payment: TPayment` — `card` или `cash`, без пустой строки; `items: IProduct['id'][]` — массив строковых ID товаров; `total: number` — сумма, отправляемая на сервер.
- `IOrderResponse` — подтверждение заказа: `id: string` — идентификатор заказа, `total: number` — сумма, подтверждённая сервером.

## Уточнения к базовым классам

Ниже уточнены сигнатуры из раздела «Базовый код» для текущей версии `src/components/base/`.

**`Component<T>`.** Это абстрактный класс: напрямую создать его экземпляр нельзя. Конструктор `protected constructor(protected readonly container: HTMLElement)` сохраняет корневой элемент. Наследник может менять содержимое элемента, но не может присвоить полю `container` другой элемент. Метод `protected setImage(element: HTMLImageElement, src: string, alt?: string): void` доступен внутри класса и его наследников; снаружи компонент можно отобразить вызовом `render(data?: Partial<T>): HTMLElement`.

**`Api`.** Тип `T` обозначает ожидаемый ответ сервера: например, при вызове `get<ICatalogResponse>('/product/')` результат имеет тип `Promise<ICatalogResponse>`. Поле `readonly baseUrl: string` хранит базовый адрес, а `protected options: RequestInit` — настройки запросов. Сигнатуры методов:

- `get<T extends object>(uri: string): Promise<T>` — получает данные.
- `post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>` — отправляет `data` в виде JSON; без третьего аргумента используется `POST`.
- `protected handleResponse<T>(response: Response): Promise<T>` — читает JSON при успешном HTTP-ответе; при ошибке HTTP промис отклоняется.

**`EventEmitter`.** Интерфейс `IEvents` описывает `on`, `emit` и `trigger`, но у самого класса есть ещё три публичных метода:

- `off(eventName: EventName, callback: Subscriber): void` — снимает конкретный обработчик. Нужно передать ту же функцию, которую передали при подписке.
- `onAll(callback: (event: EmitterEvent) => void): void` — подписывает обработчик на все события. Он получает объект с именем события (`eventName: string`) и данными (`data: unknown`).
- `offAll(): void` — удаляет все подписки, в том числе созданные через `onAll`.

Подписки хранятся в `_events: Map<EventName, Set<Subscriber>>`, где `EventName` — `string | RegExp`, а `Subscriber` — тип `Function` из стартового кода. Метод `trigger` возвращает функцию, которая при вызове объединяет переданные данные с `context` и отправляет событие; при совпадении ключей используются значения из `context`.
